# Git в VS Code: плюсы и минусы

## 3 вещи, которые удобны в VS Code

1. **Визуализация изменений (diff)**
   В панели Source Control можно кликнуть по любому изменённому файлу и сразу увидеть, какие строки добавлены, изменены или удалены. Не нужно вручную вводить `git diff` и читать вывод в терминале — всё подсвечено цветом прямо в редакторе.

2. **Встроенный редактор конфликтов**
   При merge-конфликте VS Code показывает специальные кнопки: «Accept Current Change», «Accept Incoming Change», «Accept Both Changes». Можно разрешить конфликт буквально в пару кликов, не редактируя маркеры `<<<<<<<`, `=======`, `>>>>>>>` вручную.

3. **Быстрые действия через UI**
   Основные операции — commit, push, pull, создание и переключение веток — доступны через кнопки и контекстное меню. Не нужно помнить точный синтаксис команд. Плюс расширение **GitLens** показывает, кто и когда последний раз менял каждую строку (визуальный `git blame`).

## 1 вещь, которую удобнее делать в терминале

**Сложные операции с историей (rebase, cherry-pick, reflog)**
   Интерактивный rebase (`git rebase -i`), cherry-pick, работа с reflog и другие продвинутые команды удобнее выполнять именно в терминале. В VS Code эти операции либо скрыты, либо требуют установки дополнительных расширений, а через CLI вы видите весь процесс и полностью контролируете его. К тому же на удалённом сервере (по SSH) у вас будет только терминал — навык работы с CLI обязателен для DevOps-инженера.
